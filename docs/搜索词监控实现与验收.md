更新：2026-10-25。产品入口：http://127.0.0.1:4317/#search-monitor 。这是《搜索词监控需求设计文档》的首期本地实现；下文明确当前能力与后续范围，不代表需求稿全部高级功能已交付。

## 采集与统计口径

- 当前项目自带 `scripts/capture-search-monitor.mjs`，通过隔离的 Playwright Chromium 采集，不占用用户日常 Chrome 档案。初次尝试的 OneDrive 旧采集依赖读取失败已经记录；默认运行不再依赖该目录。
- 验证站点、查询词、配送地区、DOM 商品数与所需页面。验证失败不发布排名下降结论。每次采集保留失败状态或有效快照。
- 自然位排除广告与推荐轮播。出现多个相同 ASIN 时全部保留位置，主表显示最佳位次。缺页、无效样本、未观察到都不是第 0 名。
- 一个广告父模块中的多个商品卡只计一个模块；重复商品卡保留出现次数，商品链接再按 ASIN 去重。只有落地目标的模块不补造商品卡数。
- 广告区域是页面几何区域，不等同于 Amazon Ads 后台广告位报表。视频不能直接判定为 SB，不能确认广告类型时保留 UNKNOWN。
- 广告份额分母包含未知广告主。已识别广告模块为采样口径，不能等同真实曝光、点击份额或预算占比。
- 定时广告加权份额 = 同环境、同版本有效定时快照内该品牌广告模块合计 / 全部广告模块合计；手动核对不增加权重。
- 销量只能在同来源、同类型、同站点、同统计周期、同币种内汇总。父体数据覆盖的子体不重复计数；父体销量是整个父体口径。当前货架成员会变化，做固定商品比较应建立固定集合。
- 页面 `bought in past month` 标签保留原文，不转换成精确销量。当前没有接通第三方销量 API 或卖家官方销量自动同步。

## 告警门槛

经营告警只使用定时采样，需连续两次完整、同版本有效结果。缺页或失败会中断连续判断。

| 规则 | 首版门槛 |
|---|---|
| 连续未观察到 | 前 7 天至少 5 份基线，目标 ASIN 基线出现率 ≥80%，最新连续两次未观察到 |
| 跌出 Top20 | 前 7 天至少 5 份基线，基线进入 Top20 比例 ≥80%，最新两次排名 >20 或未观察到 |
| 自然位下降 | 对最新两次各取过去 7 天同采样小时基线，各至少 5 份；两次均比中位数下降 ≥10 位 |
| 品牌广告份额变化 | 每次至少 10 个广告模块、未知广告主份额 ≤20%；同采样小时各至少 5 份基线；连续两次同方向变化 ≥10 个百分点 |

同一对象与规则合并活动提醒，24 小时冷却。有效恢复后相关规则可自动标记恢复。品牌映射纠错或采集版本改变不当成经营波动。

## 验收证据与实际限制

本轮完整测试集 50 项通过，其中新增搜索监控检查 13 项。自动检查包括跨页第 86 位、重复 ASIN 保留、SB 父模块与子卡去重、SP 视频类型、缺页邮编改写、未知品牌分母、手动样本隔离、夏令时、同小时基线、销量周期与父子去重、CSV 注入保护、数据库持久化、不可变环境、固定集合、导入幂等及撤销、离线漏采、来源和 ID 验证。运行方式：先启动应用，再执行 `npm test`。

浏览器验收覆盖新建草稿与保存跳转、真实快照详情、广告类型过滤、品牌下钻、单 ASIN 趋势、销量缺数提示、HOMA 空状态和 390 px 手机布局。临时 QA 监控与销量测试记录已清理；真实采集失败记录保留。

真实页面已经验证三个词各 3 页、自然位与 SP 模块。SB 嵌套模块已用独立结构测试验证，首批真实样本未覆盖全部广告形式。页面布局变更、轮播懒加载与第三方投放差异仍需要持续抽查原页截图，不能承诺识别所有广告。

首批 `indoor security camera` 的 50 个去重 ASIN 中，仅 4 个命中现有核实品牌映射，其余 46 个保留为未知；2 个广告模块的广告主均未确认。因此当前品牌份额不能用于判断完整竞品格局，页面与规则明确显示 / 使用这一覆盖限制。首版支持有证据的人工映射，尚未上线批量详情页品牌自动核实。

HOMA 真实 ASIN 和父子关系尚未提供，专属看板保持待配置。没有编造 HOMA 产品或历史自然位。销量来源尚未提供，正式销量表保持空白；导入功能已验收。

## 运行与维护

```sh
npm install
npm run monitor-setup  # 幂等添加候选词草稿及已有核实 ASIN，不覆盖编辑
npm start              # 同时启动网站与搜索采集 worker
```

依赖 Node ≥22、项目 PostgreSQL 和可用 Chromium。可用 `SEARCH_CHROMIUM_PATH` 指定浏览器可执行文件。默认滚动 24 小时最多请求 300 页，含重试；用 `SEARCH_DAILY_PAGE_LIMIT` 调整。额度是采集请求保护，不代表有付费数据服务预算。

如需 worker 独立运行，对网站进程设置 `SEARCH_WORKER_DISABLED=1`，另运行 `npm run monitor-worker`。数据库 advisory lock 保证同一数据库只运行一个搜索 worker。禁止多个浏览器登录档案共用。

数据表前缀为 `search_`，服务启动幂等建表。证据保存在 `.runtime/search-monitor/runs/<job-id>/attempt-N/`。截图与结构化历史当前保留在本机，首版未启用自动清理策略；需结合磁盘容量后续设置。升级前数据库备份为 `.runtime/before-search-monitor.dump`。
