# 北向亚马逊搜索词监控需求设计文档

版本：V0.9 需求评审稿  
日期：2026 年 10 月 25 日  
所属项目：北向 NORTH 个人资讯与竞品工作台  
适用人员：产品负责人、亚马逊运营、广告运营、数据开发、前后端开发、测试

在北向现有竞品监控基础上新增“搜索词监控”，持续记录指定搜索词下的自然排名、广告构成、品牌商品覆盖、样本商品销量与 HOMA 表现。用户应能从“今天发生什么变化”进入具体搜索词、品牌和 ASIN，再打开当时的页面证据，判断是否需要调整页面、广告或经营动作。

本稿给出可以拆分开发任务的产品规则、计算口径、交互、数据结构和验收标准。首期运行参数采用建议值，待确认清单见第 19 节。文中的演算数据均为验收示例，不代表任何品牌的真实表现。本次交付为需求设计，监控服务尚未启用。

## 1 业务目标与现有基础

### 1.1 要解决的业务问题

| 用户问题 | 产品应给出的答案 | 下一步用途 |
| --- | --- | --- |
| 同一个产品的自然位在上升还是下降 | 指定词、站点、环境下的最近排名、变动、趋势、出现率与原始快照 | 识别需要检查的商品和搜索词 |
| 搜索页面上有哪些广告以及多少个 | 广告产品类型、素材形式、页面区域、模块数、商品卡数、落地链接 | 判断竞争集中在哪类广告和位置 |
| 不同品牌各占多少商品链接 | 品牌去重 ASIN 数、产品家族数、自然与广告覆盖、头部自然位占比 | 判断品牌在该搜索结果样本中的覆盖 |
| 不同品牌的销量如何 | 搜索样本中商品的同来源、同周期估算销量，以及覆盖率；HOMA 可另接官方自有销售数据 | 辅助判断样本中的竞争规模 |
| 哪些品牌正在增加广告占位 | 分类型、分区域的采样广告占位份额、出现频率和同期变化 | 识别需要进一步核查的广告变化 |
| HOMA 在哪些词上变强或变弱 | HOMA 产品 × 搜索词矩阵、Top10／20／50 覆盖、前页出现率、异常列表 | 安排运营检查与验证任务 |

“搜索词”指消费者在 Amazon 前台实际输入的查询文本；“广告关键词”指广告账户中的投放对象。二者分开存储，本模块首先监控前台搜索结果。

### 1.2 与现有北向模块的关系

当前项目使用独立 HTML/CSS/JavaScript 前端、Node.js 服务和 PostgreSQL，已有品牌、产品、平台链接、价格观察、品牌公告及来源核对记录。项目文件中已设置自有品牌 `homa-us`，但官网、型号和 ASIN 尚待确认；现有美国站价格快照采用配送邮编 60202、未登录环境。

新增模块复用品牌身份与已有商品档案，通过独立搜索快照表保存多次出现和时间变化。搜索发现的陌生品牌先进入候选目录，不自动挤入用户维护的重点竞品列表。价格、公告和搜索趋势可以互相跳转，但不得仅因时间接近就给出因果结论。

依据：项目 [README](../README.md)、[品牌初始化记录](../data/competitors-2026-10.mjs)、[数据库定义](../lib/db.mjs)、[竞品接口](../lib/competitors.mjs)。

### 1.3 产品成功标准

1. 用户从总览进入任意一次 HOMA 排名异常，在三次主要点击内看到搜索词、变化和两次证据。
2. 每个汇总数都能展开到参与计算的快照、广告模块或商品集合。
3. 采集失败、未出现、识别失败、无销量来源分别呈现，不能统一显示为 0。
4. 首期必须贯通“配置 → 实际采集 → 质量检查 → 历史趋势 → 变化提醒 → 证据回看”。只有静态展示或手工截图导入不能宣称持续监控已完成。
5. 品牌销量属于完整需求。未接通有效来源时，可先上线可用的排名与广告部分，但销量功能须明确标为未完成，不能用购买提示或排名代替验收。

## 2 首期范围与建议配置

以下为设计默认值，不代表用户已确认，更不代表已经创建采集计划。

| 项目 | 首期建议 | 可扩展要求 |
| --- | --- | --- |
| 站点 | Amazon US | 数据层支持多站点，站点间独立比较 |
| 配送地区 | 60202，沿用现有项目记录 | 按配送地区建立独立环境 |
| 设备 | 桌面浏览器，1440 × 900，DPR 1 | 移动网页单独成组；App 不混入网页 |
| 会话 | 未登录、专用采集环境 | 保留语言、配送地、Cookie 策略版本 |
| 搜索条件 | 原始精确词、默认排序、不加价格或品牌过滤 | 类目限定、排序、过滤均属于独立监控配置 |
| 采集范围 | 每个词前 3 页，逐页完整滚动加载 | 实际页数和自然位深度动态记录，不能假定每页 48 个商品 |
| 初始规模 | 先以 10 个词试运行，稳定后按 30 个词测算 | 单词、关键词组、站点可分别设优先级 |
| 频率 | 每天当地 08:00、14:00、20:00 | 普通词可每天一次；活动期可单独加密 |

| 趋势窗口 | 7／30／90 天及自定义区间 | 日、周、月汇总；保留原始采样点 |
| 销量更新 | 按来源真实刷新频率，先设计每日同步一次 | 不把每天重复取得的月销量相加 |
| 提醒渠道 | 北向站内提醒与异常中心 | 外部邮件、飞书等另配置，不作为首期依赖 |
| 数据保留 | 结构化明细 24 个月，原始页面与截图 90 天 | 被告警或报告引用的证据延长至 12 个月，可配置 |

首期覆盖搜索页面主结果、带明确广告证据的模块、附加推荐模块的独立记录。PDP 广告、全品牌全部商品销量、全天真实广告展示份额、竞争对手点击量或花费不属于搜索页面可直接提供的数据；可作为后续独立数据源能力。

## 3 核心对象与可比条件

### 3.1 对象关系

一个监控计划包含多个搜索词；每个“搜索词 × 环境版本 × 计划时段”生成一次逻辑采集任务。任务产生多个页面快照，页面包含模块，模块包含商品卡或品牌店入口。商品通过“站点 + ASIN”关联品牌与产品家族。销量通过独立统计周期关联商品，不能直接挂到每次广告出现上再累加。

| 对象 | 唯一身份或关键规则 |
| --- | --- |
| 搜索词 | 站点 + 查询文本 + 类目范围；保留原始输入及实际请求文本 |
| 词组 | 用户组织和汇总使用，成员变更有生效时间与版本 |
| 监控环境 | 站点、邮编、设备、视口、语言、登录状态、排序、过滤、会话策略、采集范围 |
| 品牌 | 规范品牌 ID、展示名、审核后的别名；不同站点可指向同一品牌，但数据不直接合并 |
| 商品 | 站点 + 子 ASIN；原始 URL 与去跟踪参数后的规范 URL 都保存 |
| 产品家族 | 已验证父 ASIN 或人工产品族 ID；无关系证据就保留独立商品 |
| 广告模块 | 某页面某次采样中的独立广告容器；同模块多个点击链接不能重复计数 |
| 广告落地目标 | 商品 ASIN、品牌店／店内页面 ID、其他 URL；目标可为空且记录原因 |
| 证据 | 原始页面／数据响应、截图、时间、来源、内容哈希及解析版本 |

关键词可按类目词、场景词、功能词、品牌词、竞品词分组。词形变化、单复数和近义词不自动合并；分组也不改变精确词身份。系统保存 Amazon 自动纠正、重写查询及“改为搜索……”证据，改写后的结果不得静默算入原词连续趋势。

### 3.2 可比性约束

计算变化时，站点、精确词、配送地、设备、语言、排序、过滤、登录策略、页深、采集方法及指标版本必须一致。更换数据供应商、主要解析规则或品牌映射后生成版本断点；经过同一批原始证据重算后才能恢复连续对比。

自然排名按主结果序列计算，不能用行列或像素位置替代；首屏、行列、像素等指标必须额外保持视口与滚动策略一致。月销量对比要求来源、统计周期类型、商品粒度和集合口径一致。

历史数据默认按当时已知身份显示；品牌纠错可显式重算历史，并记录操作者、旧值、新值、原因及受影响范围。纠错不能悄悄变成一个新的经营增长信号。

## 4 自然排名与页面位置口径

### 4.1 同时保存四种位置

| 字段或界面名 | 定义 | 用途 |
| --- | --- | --- |
| 自然位 | 主搜索结果序列中，排除已确认广告及附加推荐模块后，按可见顺序得到的位次 | 比较自然搜索位置 |
| 商品卡位置 | 主结果流中的商品卡顺序，包含主流内广告商品卡 | 观察广告插入后的商品排列 |
| 页面位置 | 页码、模块序号、模块内卡序、可识别时的行列 | 原样复现页面上下文 |
| 可见区域 | 相对文档的坐标、页面尺寸、首次首屏可见比例 | 区分自然位改善与屏幕位置变化 |

跨页自然位 = 前面所有完整有效页的自然卡数 + 当前页自然位。不能用“页码 × 固定页容量”推算。若前页缺失，后页可保留页内位置，但跨页自然位为空。

“本页顶部／中部／底部”“初始首屏”是本系统可观测区域；Amazon Ads 后台的广告位分类单独存放，不能通过屏幕坐标直接等同。第二页顶部不应被标成“首页顶部”。SP 可出现在搜索结果顶部、旁侧或内部等区域，具体出现以快照为准。[Amazon Sponsored Products](https://advertising.amazon.com/solutions/products/sponsored-products)

### 4.2 重复商品与推荐模块

同一 ASIN 自然和广告同时出现时分别保存。自然结果中同一 ASIN 出现两次时，两个自然位置都保留；商品摘要显示其最好自然位及重复次数。计算后续位置不删除前面的重复卡片，以免重排原始货架。父子变体在原始观察中不合并，产品家族视图另外聚合。

“推荐”“高评分”“近期浏览”等附加模块单独记录，不计入主结果自然位；是否收费以明确广告标识或可靠来源证据确定。无法确定一张主结果卡是否为广告时标为待识别，该位置之后受影响的自然位不得当作精确值发布。

### 4.3 未出现与缺数

| 情况 | 前台显示 | 计算规则 |
| --- | --- | --- |
| 有效范围内发现商品 | 如“自然第 12 位 · 第 1 页” | 可计算排名变化 |
| 所有配置页完整，未发现目标 | “本次前 3 页未观察到” | 不赋值 0、999 或第 N+1 位；可计入未出现次数 |
| 页面真实提前结束 | “结果仅 2 页，本次未观察到” | 保存结束证据，按实际范围计算 |
| 验证码、网络错误、地区未确认 | “本次采集失败／环境未核实” | 排除业务分母，不算排名下降 |
| 只成功部分页面 | “已采集 2/3 页” | 仅开放范围足够的指标；全范围出现率不计入 |
| 商品在广告里出现，自然区没有 | “广告已出现；自然区未观察到” | 两种状态独立 |
| 尚未开始监控 | “尚无采集记录” | 不生成历史趋势 |

自然位属于受控环境中的观察值。首期不承诺代表所有买家的统一位置，也不由一次未出现推断下架、断货或停止投放。

## 5 指标字典与计算规则

除非另有说明，指标限定于同一搜索词、同一环境、同一采集范围、同一有效快照集合。份额显示分子与分母；百分比变化使用“百分点”，排名变化使用“位”。

### 5.1 商品与品牌自然指标

| 指标 | 公式或规则 | 展示要求 |
| --- | --- | --- |
| 最近自然位 | 最近有效快照内该 ASIN 最好自然位 | 同时显示观察时间；不是缓存页面打开时间 |
| 排名提升位数 | 上次可比自然位 − 本次可比自然位 | 18 → 11 显示“上升 7 位”；缺任一端则不计算 |
| 日自然位 | 当日各计划时段有效且已出现的自然位中位数 | 标注“出现时中位数”，同时给出出现率；偶数样本可为小数 |
| 自然出现率 | 发现目标的有效完整快照数 ÷ 有效完整快照数 | 如 2/3 次，66.7%；失败不作分母 |
| Top N 出现率 | 目标自然位 ≤ N 的有效快照数 ÷ 可判断 Top N 的有效快照数 | N 默认 10、20、50；深度不足且未发现不能判为未进榜 |
| 品牌自然占位份额 | 品牌主结果自然卡次数 ÷ 全部主结果自然卡次数 | 包含重复占位，未知品牌保留在分母 |
| 品牌 Top N 占位份额 | 品牌在前 N 个自然位置的卡数 ÷ 实际有效位置数 | 结果不足 N 时显示实际数量，禁止补足到 N |
| 品牌商品链接数 | 观察范围内去重“站点 + 子 ASIN”数 | 自然、广告、两者交集、两者并集分别提供 |
| 品牌产品家族数 | 有证据的产品族去重数 + 未归组独立 ASIN 数 | 显示关系确认率；不能把所有未知并为一个父体 |
| 新进入／退出样本 | 两个可比快照商品集合的差集 | 称“首次观察到／未再观察到”，不能直接叫新品／下架 |

“日自然位变动”以两天的日中位数比较；“最近一次变动”以两个具体快照比较；“较昨日同时段”只比同一计划时段。界面必须让用户知道当前比较的是哪一种。

### 5.2 广告指标

| 指标 | 公式或规则 | 解释边界 |
| --- | --- | --- |
| 广告模块数 | 独立、明确收费的广告容器数 | SP 商品卡可各为一个模块；SB 集合整体为一个模块 |
| 广告商品卡数 | 广告模块中已展示的商品卡实例数 | 不将同一卡的图片、标题、按钮链接算成多卡 |
| 广告商品数 | 广告目标去重 ASIN 数 | 与模块数分开；品牌店广告可无 ASIN |
| 类型构成 | 按广告产品与素材形式分别统计模块数和占比 | 无法识别类型的收费广告计入“类型待识别” |
| 品牌采样广告占位份额 | 归属该展示品牌的广告模块数 ÷ 全部有效广告模块数 | 默认核心指标，简称“采样广告占位”；不叫真实曝光份额 |
| 类型或区域份额 | 指定类型或区域内品牌广告模块数 ÷ 该类型或区域全部广告模块数 | 选择条件同时约束分子、分母 |
| 品牌广告出现率 | 至少出现该品牌一个广告模块的有效快照数 ÷ 有效快照数 | 零广告快照也在出现率分母内 |
| 广告商品卡品牌份额 | 品牌广告商品卡实例数 ÷ 全部广告商品卡实例数 | 单独视图，不与模块份额混用 |
| 主结果广告密度 | 主结果中广告商品卡数 ÷ 主结果全部商品卡数 | 独立横幅不进入此分母 |
| 品牌份额变化 | 本期份额 − 基期份额 | 20% → 30% 为 +10 个百分点 |

某快照没有广告时，模块数为 0，模块份额为“无广告，无法计算”，不画成 0% 的品牌竞争份额。品牌归属未知的模块保留在总分母中，显示未知份额；不能只拿已识别品牌重新算到 100%。

日／周默认采用“模块数汇总之比”：Σ品牌模块数 ÷ Σ全部模块数。另提供“逐快照份额均值”时必须单独命名，不与前者互换。对比两期时使用同一词、同一时段的共同有效样本配对集合，并显示匹配覆盖率；手动补采和失败重试不能增加某一期的权重。

跨词总览默认先在各词内计算，再对固定词组等权汇总，同时展示逐词分布。没有真实、同周期的词流量时，不声称按市场流量加权。跨词商品数量先去重，跨词销量同样先去重。

### 5.3 算例

以下均为虚构验收数据。某次页面有 10 个广告模块，其中 6 个 SP 商品卡、2 个 SB 商品集合、1 个视频模块、1 个类型待识别模块；两个 SB 集合各含 3 张商品卡，视频含 1 张商品卡，待识别模块无商品卡。因此广告模块数为 10，已识别广告商品卡数为 13。

若品牌 A 占 3 个模块，其中一个 SB 集合有 3 张商品卡，则 A 的模块份额为 3/10 = 30%；若其余两模块各一张卡，商品卡份额为 5/13 ≈ 38.5%。这两个指标都有效，但回答不同问题。

同一天两个可比快照，A 分别占 3/10 和 1/2：模块汇总份额为 4/12 = 33.3%，逐快照份额均值为 40%。系统默认显示前者，详情保留两次分母。

## 6 广告识别与品牌归属

### 6.1 三个独立分类维度

| 维度 | 枚举建议 | 识别依据 |
| --- | --- | --- |
| 广告产品 | SP、SB、Display 可确认类型、其他已确认广告、类型待识别 | 来源字段、广告标记、模块结构及可审计证据 |
| 素材形式 | 图片商品卡、商品集合、品牌店聚焦、视频、展示横幅、其他 | 实际可见素材与目标结构 |
| 页面区域 | 首页顶部、主结果流、侧栏、页尾、其他；另存页码及首屏标记 | 页面坐标、结构和相对自然结果的位置 |

SP 已支持视频，SB 视频也可出现在搜索结果与商品详情页，因此“视频”本身不能证明广告属于 SB。未识别的横幅也不能直接标为 Display 或 DSP。[SP 视频官方指南](https://advertising.amazon.com/library/guides/sponsored-products-video)、[SB 视频官方指南](https://advertising.amazon.com/library/guides/getting-started-with-sponsored-brands-video)

类型判定保存依据与置信状态：已确认、待复核、无法识别。保留明确 Sponsored 证据但产品类型未知时，仍计入付费模块总量。仅靠模型猜测广告类型的结果不进入正式分类型统计。

### 6.2 广告模块计数原则

1. 一个 SB 集合即使包含三个 ASIN、Logo 和多个 CTA，也只计一个模块；目标表可以有多条记录。
2. 同一个广告在同页不同位置确实出现两次，计两个模块；同一个 DOM 节点被解析器重复发现，只计一次。
3. 品牌店链接归一到店铺或店内页面 ID。不同跟踪参数不构成新的品牌店或新商品。
4. 轮播默认只计算约定滚动流程中实际呈现的卡片。隐藏卡片不进入“已观察商品卡”分母；如主动翻动轮播，需作为独立采集策略版本。
5. 不点击付费广告以验证落地；优先读取页面目标信息、已获数据响应或规范化目标 URL。确需产品补充信息时直接请求规范商品地址，并计入独立任务。

### 6.3 品牌与广告主分开

默认看板统计“广告展示品牌”：SP 采用已核实商品品牌，SB 优先采用创意／品牌店的明确品牌。广告购买者、代理商、卖家与商品品牌不是同一个对象；没有可靠证据时广告主字段留空。

一个模块只进入一个展示品牌桶。明确多品牌的模块记入“多品牌”，品牌未知记入“未知”，不拆成多份导致模块份额总和超过 100%。模块内商品卡可以按各自品牌另算商品卡份额。

品牌标准化优先级：已确认站点 ASIN 映射 → Amazon 商品品牌字段／品牌店证据 → 人工审核映射。标题中的兼容品牌、卖家名称和模糊文本匹配只能提供候选，不能自动归属。

## 7 品牌销量设计

### 7.1 三种销售相关数据必须分开

| 数据 | 合适名称 | 允许用途 | 不允许的用法 |
| --- | --- | --- | --- |
| 搜索卡上的 “X+ bought in past month” | 页面近期购买提示 | 展示原文、观察日期与提示下限 | 直接当作精确件数、订单数或品牌销量累加 |
| 第三方 ASIN／父体销量 | 商品估算销量，注明来源和周期 | 同源、同周期、无重叠商品集合的样本汇总 | 宣称 Amazon 官方销量或该词带来的销售 |
| HOMA 官方授权报表 | 自有商品销量／订单量／销售额，保留原字段口径 | 自有经营分析；与排名时间对照 | 与竞争对手估算值无标记混合排名 |

竞品真实销量和该搜索词对所有品牌的精确销量贡献不设为前台抓取字段。需要搜索购买维度时，可另接有权限的 Search Query Performance 报表；其查询、ASIN、周期和购买字段按官方定义保留，不与整店销量或广告归因销量混用。[Amazon 官方 SQP 数据结构](https://github.com/amzn/selling-partner-api-models/blob/main/schemas/reports/sellingPartnerSearchQueryPerformanceReport.json)

### 7.2 默认展示的品牌销量

默认标题为“本搜索样本覆盖商品的估算月销量”，完整标签必须包含：站点、商品集合规则、统计起止日、来源、子 ASIN／父体粒度、覆盖数量、最后更新日。

计算顺序：确定商品集合 → 站点内 ASIN 去重 → 应用有证据的父子关系 → 选用同一来源和周期的销售记录 → 排除重复统计实体 → 汇总可用记录并给出覆盖率。

| 关键场景 | 处理规则 |
| --- | --- |
| 同 ASIN 同时出现在自然和广告 | 销量只计一次 |
| 同 ASIN 出现在多个监控词 | 词内可以各展示，跨词品牌汇总只计一次 |
| 来源只提供父体销量 | 每父体计一次，并标注“包含该父体其他变体，可能超出搜索可见子 ASIN” |
| 同时有父体总量和部分子体销量 | 固定一种不重叠粒度，禁止父体 + 子体相加 |
| 来源粒度不明 | 可展示单条原值，但暂不纳入品牌合计 |
| 10 个目标商品只有 6 个有估算销量 | 显示“已覆盖 6/10，已覆盖商品合计”；不得填补另外 4 个 |
| 页面出现 “1K+” 提示 | 原文保留，可解析提示下限 1000；销售件数字段保持空值 |
| 未找到销量来源 | 销量区显示来源未接通，链接数与排名继续工作 |
| 同商品每日取得同一个近 30 天数值 | 保留数据更新时间；不累加为当月总量 |

品牌对比表提供“当前货架集合”和“固定对照集合”两种模式。前者回答当前搜索结果包含哪些销量规模的商品；后者锁定基期商品集合，帮助观察同一批商品的销量变化。新进与退出商品单列，避免把商品集合变化误写成销量增长。

固定集合的成员退出页面后仍需同步其销量。前后期只有共同有值的商品参与可比增长计算，并同时显示共同覆盖／固定全集数量、缺数清单与不同期完整合计。滚动 30 天值之间可展示差额，但明确窗口重叠，不能推算单日销售。

### 7.3 销量份额的适用范围

仅在同源、同周期、同粒度的有效销售集合中计算“已覆盖样本销量份额”。它不是该关键词真实成交份额，也不是全类目或品牌全店市场份额。覆盖不一致时默认展示数量与覆盖情况，份额标为样本口径；来源或商品集合改变后停止直接同比环比。

估算销售额优先使用来源直接提供值。只有明确需要时，才另列“估算销量 × 观察价格”的推导值，并说明价格时点与促销偏差；不冒充来源提供的收入数据。

## 8 HOMA 专属监控

HOMA 与其他品牌共享采集和计算规则，增加自有品牌视图、目标配置与提醒优先级。使用项目已有 `homa-us` 作为关联入口，显示名称可统一为 HOMA；具体商品归属仍需准确 ASIN 或品牌店证据。

### 8.1 产品与关键词矩阵

行是 HOMA 子 ASIN／型号，列是已配置搜索词。每个单元格显示最近自然位、最近变动、7 天出现率和更新时间；点击进入趋势抽屉。支持切换父体视图，父体排名采用各子体最好位置，但同时展示贡献子体，避免变体替换被误读为单一产品进步。

HOMA 总览显示：已监控型号数、已配置词数、最近有效采集覆盖、进入 Top10／20／50 的目标商品词对数、自然出现率、采样广告占位、待处理异常。总览的词对分母来自明确的监控关系，不自动生成所有商品与所有词的笛卡尔积。

### 8.2 重点分析

| 功能 | 内容 |
| --- | --- |
| 自有排名趋势 | 最近点、日中位数、原始点、出现率；缺失断线，不以 0 连线 |
| 自然与广告同时展示 | 自然位趋势与广告出现记录上下联动，共用时间轴 |
| 自有产品重叠 | 同词多个 HOMA ASIN 同时占位、轮换或竞争；列事实，不直接判断内部竞价 |
| 重点词目标 | 可配置每个 ASIN 的目标自然位、稳定出现率、重点关注周期 |
| 竞争对照 | 选择 3–5 个竞品 ASIN，与 HOMA 同条件比较 |
| 变化解释辅助 | 同期价格、优惠、评分、评论、库存观察、公告、活动标记 |
| 检查任务 | 异常加入待办，记录负责人、检查结论、动作、后续复查日期 |

产品线示例可以包含现有项目关注的室内摄像头，但正式词表与 HOMA 商品能力需由真实档案确认。HOMA、G-Homa、Homatics 或其他近似名称不自动合并。

## 10 页面结构与交互设计

### 10.1 导航

北向左侧一级导航新增“搜索词监控”，建议入口 `/#search-monitor`。进入后保留站点、关键词组、日期和环境选择；下设六个视图：监控总览、搜索词详情、品牌对比、HOMA 看板、异常中心、采集设置。现有“竞品监控”的品牌页增加“查看该品牌搜索表现”。

所有视图顶部固定展示当前范围，例如“美国 · 60202 · 桌面 · 前 3 页 · 近 7 天”；旁边显示计划快照数、有效数和最近成功时间。筛选状态写入可分享的本地页面路由参数，返回上级后不重置。

### 10.2 监控总览

```text
搜索词监控     [美国] [词组] [近7天] [桌面·60202]    新增监控
有效采样  /  HOMA目标词对  /  排名下降待查  /  广告占位变化

需关注的变化                 HOMA产品与搜索词矩阵
可点开证据的事件列表         自然位·变动·出现率·更新时间

搜索词清单
词 | HOMA最好自然位 | 较昨日 | 自然链接数 | 广告模块数
   | 主要展示品牌 | HOMA采样广告占位 | 数据覆盖 | 详情
```

按异常优先级、关键词重要度或最近变化排序。卡片显示真实 0、空值和样本不足三种状态。不能将不同词的第 1 位简单平均后命名为“HOMA 总排名”。

### 10.3 搜索词详情

顶部展示精确词、请求 URL、实际查询文本、采样环境、最新／历史时点、同条件比较按钮。正文提供“货架快照、自然位、广告、品牌与销量、变化记录”五个页签。

| 页签 | 核心内容 | 交互 |
| --- | --- | --- |
| 货架快照 | 按原页面顺序重建模块，广告、自然、附加推荐分别标识 | 卡片显示 ASIN、品牌、双位置、价格、评分、购买提示；打开证据 |
| 自然位 | ASIN 趋势、排名变动榜、进入退出列表 | 多选商品、切原始点／日汇总、反向排名轴、拖选时间 |
| 广告 | 模块数量、类型结构、区域分布、品牌份额 | 类型／区域 → 品牌 → 广告模块 → 目标商品或店铺 |
| 品牌与销量 | 链接数、家族数、自然份额、广告份额、样本销量与覆盖 | 自然／广告／并集、当前／固定集合、来源与周期筛选 |
| 变化记录 | 排名、占位、商品集合和素材变化事件 | 两时点对照、加入检查任务、填写结论 |

货架卡片不必像素级复刻 Amazon，但必须保留顺序与模块边界。截图打开后定位到对应模块；若只有结构化 API 数据，标为“数据快照，无页面截图”，不能伪装成网页截图。

### 10.4 品牌对比

品牌行显示：品牌名、观察到的去重 ASIN 数、产品家族数、自然 Top20 占位、广告模块数、采样广告占位、广告出现率、估算销量、销量覆盖、两期变化。未知品牌与多品牌单列。

支持品牌点击下钻到 ASIN。单商品列表同时显示自然与广告状态，销量只出现一份。一个品牌的链接数量不能解读为其全站全部在售链接数。横向对比图中真实自有销量与第三方估算使用不同图层，默认不拼成同一排名。

### 10.5 HOMA 看板与趋势抽屉

默认展示自有产品 × 搜索词矩阵和待查异常；支持按产品线、型号、词组、目标状态筛选。抽屉包含时间趋势、实际出现状态、竞品对照、证据、同期经营事件。排名图纵轴上方表示更好名次，缺失区用空档或状态标记；颜色之外提供文字箭头与数值。

### 10.6 设置与导入流程

新增监控：输入词或导入词表 → 选择站点和环境 → 绑定 HOMA 目标 ASIN → 设置频率和提醒 → 展示预计请求量与已配置成本 → 保存为草稿或启用。关键词重复时给出已存在项；归档只停止未来任务，历史仍可查。

销量导入：选择数据文件与来源 → 映射列 → 预览统计周期、粒度、币种和重复情况 → 显示将新增／更新／拒绝的行数 → 提交 → 生成可回滚批次。界面禁止把购买提示列映射成精确销售件数而不提示语义冲突。

### 10.7 通用状态与可访问性

支持首次空状态、加载中、局部失败、无匹配结果、采集中、暂停、来源未授权、源过期及部分覆盖。表格固定关键身份列，窄屏横向滚动；手机端优先保留异常和 HOMA 查询，复杂矩阵提供列表模式。所有按钮可键盘操作，图表附同口径明细表。

## 11 采集计划与数据源要求

### 11.1 数据源职责

| 数据源类别 | 提供内容 | 接入条件 |
| --- | --- | --- |
| 搜索页面采集或搜索数据服务 | 排序、页、模块、自然／广告、品牌、目标、价格、评分 | 能还原所需页深和广告结构；提供时间、地区及证据 |
| 第三方销量服务或导出 | ASIN／父体估算销量、周期、可用历史 | 确认当前账户权限、合法使用范围、粒度与刷新延迟 |
| HOMA 官方业务报表 | 授权范围内商品销量、销售额、库存等 | 单独凭证、市场与时间口径匹配 |
| 品牌分析与广告报表 | 授权范围内查询购买、广告曝光点击、归因销售 | 单独指标体系，不当作所有竞品前台曝光数据 |
| 人工核对 | 品牌纠错、广告类型纠错、验收标注 | 必须带证据与修改日志 |

数据供应商尚未确定。卖家精灵等用户已有来源可以优先评估，但本稿不假定其现有套餐提供实时 API、完整广告模块或全部历史。先通过能力验证，再确定采购或技术方案。

### 11.2 来源能力验证

选取 5–10 个有代表性的真实词，在相同环境核对实际页面：普通商品网格、混合广告、视频、SB 集合、轮播、结果提前结束、无广告、重复 ASIN。必须验证广告模块及子卡没有被数据 API 预先合并丢失，品牌店落地能保存，地区条件可信。

若候选接口只返回“前 N 商品 + sponsored 布尔值”，它可以支持部分排名监控，不能据此验收完整的广告类型、模块数量和品牌店占位需求。采集适配器需声明自己支持哪些指标，不支持的指标显示不可采集。

### 11.3 调度和重试

每个计划时段生成唯一逻辑任务。多页顺序采集，记录每页开始／结束时间；建议一次快照跨度不超过 15 分钟，超过则标为非同步组合，不能拼成某一时刻的完整货架。

临时网络错误按退避策略最多重试 2 次。验证码、访问限制、登录失效和地区设置失败分别记录，不绕过访问控制。重试超出时段允许延迟后，不将当前结果回填为过去时刻；若重采整个时段，以被选定的一组一致页面作为唯一正式快照，其他尝试只留审计记录。

计划时段允许延迟建议为 30 分钟。手动采集属于独立观察，默认不进入固定时段趋势分母；用户可以查看，但不能用手工多采某个品牌或某个词来改变周期份额。

使用数据库任务表、唯一键及带到期时间的租约防止重复 worker 执行。机器休眠或服务退出后，过期任务标为“错过”；恢复后采集当前时点，禁止伪造历史。若需要连续覆盖美国当地时段，应部署常驻 worker 或选用可调度的外部服务。

### 11.4 采集成本

基础页面请求量 = 词数 × 站点数 × 环境数 × 每次页数 × 每日次数。按 30 词、1 站、1 环境、3 页、3 次计算，为 270 页／天，按 30 天为 8,100 页／月；不含失败重试、详情补充、销售查询与证据存储。

数据服务计费可能按请求、页、任务或额外字段收费。系统必须使用实际供应商单位费用计算预算，不在本稿中给出未经核实的金额。设置日／月预算上限、重试上限、单域并发上限和使用量提醒；超额后停止低优先级采集并显示覆盖缺口，不自动提高消费额度。

## 12 变化事件与提醒规则

提醒分为业务变化、数据问题两类。每条事件包含对象、规则、阈值、基期／本期、分子分母、证据、触发原因、首次与最近出现时间、处理状态。规则默认仅提示和创建站内待查项，不自动调整广告或商品页面。

### 12.1 建议初始规则

以下阈值是可调配置示例，不是已验证的统计显著性阈值。上线先观察 7 天，按实际波动校准。

| 规则 | 初始触发条件 | 前置条件 | 建议检查 |
| --- | --- | --- | --- |
| HOMA 自然位明显下降 | 两个连续有效计划采样均比各自过去 7 天同一时段中位数差至少 10 位 | 每个时段至少 5 个基线有效排名；当前均有排名 | 页面、价格、库存、相关性及竞品变化 |
| HOMA 跌出 Top20 | 原先稳定在 Top20，连续两次可判断 Top20 的快照未进入 | 基期最近 7 天至少 5 次有效观察且进入率 ≥80% | 先看证据，再判断经营原因 |
| HOMA 未观察到 | 连续两次完整采集未发现，且此前出现稳定 | 不是采集失败或解析异常 | 补查 ASIN 可售状态、变体或查询变化 |
| 品牌广告份额增加 | 当前完整日比前 7 个完整日基线高 ≥10 个百分点 | 同一时段配对、当前至少 3 次有效快照、当前 ≥20 模块、基期 ≥100 模块且覆盖 ≥80% | 查看增加的类型、区域、素材和目标 |
| 头部出现新品牌 | 最近 3 次有效快照中至少 2 次进入自然 Top10 | 同环境，有足够此前有效记录 | 查看首次观察证据与对应 ASIN |
| HOMA 进入目标位 | 连续两次进入配置目标，并满足出现率条件 | 两次快照有效 | 记录达标，不以单点认定稳定提升 |
| 销量估算明显变化 | 相同固定集合、同来源完整月份变化达到用户阈值 | 两期共同销量覆盖 ≥90%，粒度与方法未变 | 查来源修订、促销、集合与真实经营记录 |
| 采集或识别异常 | 连续失败，或关键识别率低于质量门槛 | 不依赖业务基线 | 单独发数据问题，暂停受影响业务告警 |

不能获得足够基线时仍显示原始变化，但标记“样本不足，暂不触发趋势提醒”。每天一次的配置没有每天三次的告警能力；系统应按能力降级规则并让用户看到，不能默默放宽门槛。

### 12.2 去重与生命周期

同“词 × 环境 × 对象 × 规则版本”持续异常合并成一个事件；同类事件建议 24 小时冷却。状态为新发现、已确认、处理中、已恢复、已关闭。连续两次有效观察恢复到阈值内才标恢复；没有新数据不能视为恢复。短时失败中断连续判断，不能把失败前后两次合称连续。

解析版本、品牌映射或销量供应商改变引发的跳变归类为数据修订。业务提醒必须提供当时证据和可执行检查入口，例如“查看商品状态”“比较前后货架”“打开关联价格记录”。

## 13 技术方案与现有系统接入

### 13.1 分层流程

```text
关键词与监控配置
        ↓
持久调度任务 → 搜索采集适配器 → 原始证据存储
        ↓                         ↓
逐页质量核验 ← 页面／模块／商品解析
        ↓
品牌与ASIN映射 → 指标计算 → 汇总视图 → 北向页面
        ↑             ↓
销量／自有报表     变化检测 → 异常中心 → 人工检查记录
```

继续使用现有 Node.js 与 PostgreSQL。网页 API 负责配置和读取，独立 worker 负责较长的采集及解析任务；不在 HTTP 请求里同步跑完几十页抓取，也不沿用资讯同步的内存定时器承载可靠采样。

建议新增 `lib/search-monitor/`、`public/search-monitor.js` 和专用 worker 入口。现有 `public/app.js` 增加导航，`server.mjs` 增加路由及静态文件白名单；现有品牌和商品档案只通过关联表复用，避免把高频卡片记录写入每日价格表。

### 13.3 约束和索引

计划任务对 `(monitor_id, scheduled_at)` 唯一；页面对 `(snapshot_id, page_no)` 唯一；商品卡对 `(module_id, card_index)` 唯一。不能对 `(snapshot_id, asin)` 做唯一约束，否则会丢失自然与广告重复出现。

销量逻辑键包括来源、市场、实体粒度与 ID、统计起止日、窗口类型；同键允许显式 revision。原始文件哈希相同的重复导入保持幂等。价格、评分和销量缺失允许 NULL，状态字段解释缺失原因；实际 0 与 NULL 不互换。

常用索引包括词与采样时间、ASIN 与采样时间、品牌与采样时间、告警状态与发生时间、销量实体与周期。日期使用 `timestamptz` 保存事实时间，业务日按 profile 时区派生；不能由服务器系统日期决定美国业务日。

接口名称为设计建议，可适配现有仅 GET／POST 的服务约定。所有聚合接口返回 `scope`、`period`、`data_as_of`、`coverage`、`metric_version` 和可追溯 ID。

## 14 数据质量与运行要求

### 14.1 可用状态按指标判断

同一个快照可以“自然排名可用、广告类型部分可用、销量未接通”。保存独立的排名、广告存在性、广告类型、品牌、环境、页完整性等质量状态，不能只给一个笼统成功标记。

| 检查 | 不通过时的处理 |
| --- | --- |
| 邮编、站点、语言和查询身份已验证 | 暂停进入该环境正式趋势 |
| 分页连续且各页加载完成 | 只开放有足够覆盖的局部指标 |
| 广告／自然身份可判断 | 受影响区段后续自然位不发布为精确值 |
| 广告模块边界可靠 | 不发布可能重复的广告数量及份额 |
| 品牌未知占比 | 一直显示；默认超过 10% 时不发品牌份额变化提醒 |
| 广告产品类型未知占比 | 一直显示；默认超过 5% 时不发分类型变化提醒 |
| 销量来源与周期完整 | 不进行同周期品牌合计或增长比较 |
| 解析版本变化 | 建立断点，抽检后重算或开启新基线 |

异常跳变先对照页面证据、结构变化及采集覆盖，再触发经营告警。判定异常只隔离受影响数据，不删除真实突变。

### 14.2 性能与运行指标

以下为开发验收目标，需在约定测试设备、数据规模和数据源条件下测量：

- 30 个监控词、90 天明细下，预聚合总览和品牌查询 API P95 ≤2 秒；首屏交互内容 ≤3 秒。
- 明细分页，默认每页 50 行；长周期导出不阻塞正常浏览。
- 连续 7 天试运行中，有效完整逻辑采样数／计划数目标 ≥95%；来源限制、设备休眠等造成的损失仍计入总体覆盖，另外拆因解释。
- 接入验收使用至少 30 张真实页面和至少 200 张人工核对商品卡；自然位与广告／自然身份准确率目标 ≥99%，广告类型在可判定样本中的准确率 ≥95%。同时报告未知率和各类型样本量，不能靠全部标未知通过。
- 若某种目标广告类型在试运行中未出现，标为待样本验收，不能自动宣布已验证。

### 14.3 存储与权限

沿用本机访问边界，供应商密钥保存在后端环境配置中。未来对外部署时需单独完成认证和角色权限。原始页面可能含会话标识，应清理 Cookie、认证头及个人信息；渲染证据不能执行来源页面脚本。

证据读取通过 ID 白名单映射，禁止任意文件路径访问；远程采集仅允许配置的站点与服务地址，避免把任意 URL 输入变成内网请求。CSV 导出处理公式注入，外链校验协议，商品标题和品牌文本作普通文本转义。

数据库与证据索引同步备份，定期抽验可恢复性。到期删除证据前检查是否被告警、报告或固定样本引用；删除后保留哈希与元数据，前台明确“原始证据已过保留期”。

| AC21 | 固定集合有商品退出货架或本期销量缺失 | 成员保留；更新其销量；可比增长只用两期共同有值集合并显示覆盖 |
| AC22 | 同一近 30 天销量连续同步 7 天 | 不累计成 7 倍，趋势显示每次来源时点 |
| AC23 | 邮编、设备、关键词改写或页深改变 | 新可比组或明确断点，不直接连接趋势 |
| AC24 | HOMA 与近似品牌名混杂 | 未审核不合并；确认 ASIN 才进入自有看板 |
| AC25 | 同一任务失败重试后成功、或两 worker 争用 | 一个正式时段快照；保留尝试；不增加趋势权重 |
| AC26 | 电脑休眠错过两个时段 | 两个时段标错过，恢复后记录当前时间，无历史补造 |
| AC27 | 只有一天基线或广告样本不足 | 显示变化和样本不足，不触发已配置趋势提醒 |
| AC28 | 品牌映射纠错导致份额变化 | 审计可追溯；标为数据修订，不发经营增长提醒 |
| AC29 | 重复导入同一文件后提交一份修订文件，再撤销修订批次 | 重复导入不重复统计；撤销修订后恢复原值，其他历史不受影响 |
| AC30 | 从总览 HOMA 告警进入证据 | 三次主要点击内看到两次位置与快照 |
| AC31 | 页面滚动有隐藏轮播卡或重复粘性模块 | 隐藏卡不计已观察量；同一模块不重复计数 |
| AC32 | 本次结果只有两页并真实结束 | 显示提前结束证据，实际覆盖为两页，不判定抓取失败 |
| AC33 | 原始页面含脚本、商品文本含 HTML、导出以 = 开头 | 安全呈现普通内容，不执行脚本或表格公式 |
| AC34 | 旧竞品页面与搜索模块关联 | 原有品牌、价格、资讯查询仍正常，无重复品牌污染 |

## 16 分阶段交付与上线门槛

| 阶段 | 产出 | 通过条件 |

开发顺序建议先落实来源和最小证据链，再做聚合与看板。实际工期取决于数据源、已有采集器可复用程度和 HOMA 映射完整性，在来源验证后给出估时；本稿不以未验证的接口能力承诺日期。

上线前完成：数据库备份与迁移回滚、来源配置和预算、真实样本抽查、关键验收、连续运行观察、旧模块回归。上线初期维持有限词数，按成本与覆盖逐步扩容。

## 17 范围边界与解释规则

系统自动摘要只能由指标生成，使用“观察到、样本中、同期”等与证据一致的表达。例如“品牌 A 在本词最近 3 次采样中出现 8 个广告模块，占观察模块的 32%”。

以下结论不能单靠本模块生成：竞争对手提高预算／竞价、某类广告导致销量增长、搜索排名下降由广告挤压导致、某品牌控制全部市场、未出现商品已下架。可生成对应待验证假设，并关联需要的官方报表、库存或页面检查。

首期历史从实际启用日开始积累。供应商提供的历史只有在环境、排名定义、广告范围和来源可比时才可合并；不兼容历史单列，禁止补造过去页面或把当前页面重复写成历史。
