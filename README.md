# 北向 NORTH

本地个人资讯工作台。独立 HTML/CSS/JavaScript 前端，Node.js 本地服务，PostgreSQL 持久化。界面包含四个资讯频道、年份与月份选择、月度收录柱图、紧凑资讯列表、搜索、收藏、规则详情和全年政策甘特图。

## 打开

### macOS Dock 独立应用窗口

首次在 Mac 上双击 **安装北向到Dock.command**，会在用户的 `~/Applications` 中创建“北向.app”，生成北向图标并加入 Dock。之后点击 Dock 图标，即可自动启动本项目的本地服务，在独立应用窗口中打开工作台，无需保持终端窗口。重复点击会回到同一窗口；本项目已在运行时复用服务。

首次构建需要 **macOS 12 或以上版本**、**Xcode 命令行工具**（缺少时运行 `xcode-select --install`），以及已有的 **Node.js 22+、npm 依赖、PostgreSQL 和初始化数据**。新检出仍先按 `.env.example` 配置数据库，运行 `npm ci` 和 `npm run setup`。安装器沿用当前项目目录和数据库，不复制数据库或登录凭据；本机数据库尚未启动时，启动器会尝试打开 Postgres.app。

应用支持快捷键刷新、复制粘贴、前进后退和导出下载；外部原文在默认浏览器打开。关闭窗口后可点 Dock 图标恢复。退出界面不会停止后台资讯更新与监控服务。启动问题会在窗口中提供“重试”和“查看启动日志”，日志位于 `.runtime/desktop/server.log`。若端口被其他项目或旧版服务占用，会明确提示，不会打开错误项目；旧服务应先停止后重新启动。

移动项目目录、移动 Node.js 或更新桌面启动器后，重新运行安装器即可。重复安装保留其他 Dock 图标，不重复添加北向。也可以手动将 `~/Applications/北向.app` 拖入 Dock。需要不同名称或仅安装时可运行：

```sh
node scripts/desktop/install.mjs --name 北向 --no-open
```

安装器会在 Mac 上编译并进行本机临时签名，无需 Apple 开发者账号。它生成适用于当前 Mac 架构的应用；当前 Linux 云环境可验证后台启动逻辑，macOS 窗口、签名及 Dock 行为需要在 Mac 上验收。

### 自动与手动更新

首次从旧版升级时，先退出“北向.app”，更新项目源代码后再运行一次 **安装北向到Dock.command**。这次安装会把更新组件加入独立应用，之后即可在应用内更新。

独立应用右上角和应用菜单提供 **软件更新** 区域，显示当前版本、提交号、上次检查时间和安装进度。可以点击 **立即检查**、**立即安装**，也可以分别开关 **自动检查更新** 和 **发现更新后自动安装**；两个开关默认开启。

应用打开后自动检查一次，随后每小时检查 GitHub 仓库 `JiangYu3761/Work-Board-Tasks` 的 `main` 分支。发现新版本后，会在窗口空闲至少一分钟、没有打开的表单或正在编辑的输入框时自动安装。关闭应用期间不检查。自动安装关闭时仍可手动检查和安装。

更新先下载到独立版本目录，校验 Git 对象，按锁文件安装依赖，重新构建并验证应用签名。切换前停止本应用管理的后台服务、备份 PostgreSQL；新版服务通过健康与工作台 API 检查后替换应用并自动重新打开。普通安装或启动失败会保留或恢复原代码、原应用及数据库；恢复未完成时会明确提示，备份与日志会保留供排查。

原始项目源代码、未提交改动、`.env`、原有 `node_modules`、图片证据和登录状态保留在原目录；更新版使用自己的依赖，并沿用现有配置与数据。运行版本、更新日志与数据库备份保存在 `.runtime/desktop/updates/`。自动更新仍需要本机 Git、npm、Xcode 命令行工具、PostgreSQL 的 `pg_dump` / `pg_restore`，以及该 GitHub 仓库的读取权限；这些步骤不会要求在聊天或更新窗口填写密钥。

更新源必须先发布包含 `scripts/desktop/updater.mjs` 等桌面组件的新版代码。尚未发布、网络断开或无仓库权限时，更新区域会显示原因，当前版本可以继续使用。由终端或其他启动器运行的旧服务需要先关闭，更新器不会停止无法确认归属的进程。

启动器与更新器专项检查：

```sh
node --test tests/desktop-launcher.test.mjs tests/desktop-updater.test.mjs
```

更新器测试使用临时 Git 仓库、临时后台进程与独立测试数据库；macOS 构建在 Linux 测试中由夹具替代，原生窗口、签名、应用替换与重新打开仍需在 Mac 上验收。

### 终端方式

双击 `启动北向.command`，然后访问 **http://127.0.0.1:4317**。

也可以在当前目录运行：

```sh

```

需要本机 Postgres.app 正在运行，Node.js 22 或以上版本。服务器仅监听本机回环地址。直接双击 `public/index.html` 无法连接数据库，应通过上述地址打开。HTML、CSS、JS、字体与装饰均可在不访问外部 CDN 的情况下呈现。

## 数据

- 数据库：`personal_radar`，本机 PostgreSQL 18，端口 5432。
- 连接设置位于 `.env`，不写入前端。此电脑当前使用本机 PostgreSQL 用户认证。
- 本项目有独立数据库，不读写其他项目的业务表。
- `articles`：资讯、规则摘要、日期、原文链接、收藏状态。
- `policy_events`：有出处的适用期、生效日、截止日。
- `metrics`：有明确统计口径与原文链接的图表数据。
- `sources`、`candidates`、`sync_runs`：信息源、待整理数据、同步记录。
- 2026-10-24 补入 63 条历史记录，总计 74 条：AI 31、亚马逊 18、跨境 13、美国政策 12。2026 年归档 73 条，包含 1—10 月记录与 11 月已公布的生效安排；另有 2027 年捆绑规则 1 条。这是已核实重点档案，不是穷尽式年度数据库。
- 摘要不超过 100 个字符，多数为一句话。列表不显示背景段落，原文入口与详情仍可访问。
- 归档日期优先采用发布日期，无发布日期时使用明确生效日，并在列表标为“生效”。两种日期均缺失时仅在“全部年份”中展示，不使用核实日期冒充历史日期。月份收录数量随频道、关键词和收藏条件变化。
- 支持全年或单月筛选，0 条的月份也可点击；未来月份不填充虚构新闻。所有匹配记录连续展示，不再只显示前 6 条。甘特图支持选择年份或未来 120 / 180 天。
- 初始化：`npm run setup`；只更新历史档案：`npm run archive`。可重复执行，保留收藏和其他增量内容；已存在的历史档案会更新标题、摘要、链接及日期。

## 更新能力与当前边界

已启用 Federal Register 官方 API 和 Google AI 官方 RSS。服务器持续运行期间，每 4 小时自动检查一次；也可点击“更新资讯”或运行 `npm run sync`。电脑休眠或服务停止时不会更新。

首次检查成功保存 35 条原始条目。新条目存入候选队列；未完成中文摘要或政策核验的内容不会进入主页。信息源页面显示成功时间、失败状态和待整理条目。

中文自动摘要接口当前**未配置**，不会产生模型调用费用。如需启用，在 `.env` 填入兼容 Chat Completions 协议的 `SUMMARY_API_URL`、`SUMMARY_API_KEY`、`SUMMARY_MODEL`，重启服务。每次最多处理 5 条 AI 新闻，超长或非中文摘要不会发布。只向所配置接口提交公开订阅条目的标题与摘要。政策文件即使配置模型也保持待核验，不自动推断生效日期。

AMZ123、雨果跨境、亚马逊和其他手工核实来源的持续采集尚未启用。AMZ123 文章的内容使用限制，以及亚马逊部分页面的登录和动态加载要求，需要在正式接入时单独处理。目前这些条目为独立短摘要与原文跳转。

## 竞品监控与运营视角（V1.2）

首页新增“接下来 30 天”规则节点和竞品入口；月份档案可叠加费用、履约、合规、增长主题及“仅官方来源”筛选。主题采用关键词匹配，不代表已确认的经营影响；临近节点始终以今天为起点，与档案月份分开。

竞品模块入口为 `/#competitors`，支持：

- 添加、修改、暂停标记及归档 / 恢复品牌，保存市场、币种、官网与社媒 / 店铺链接。已有产品后锁定市场和币种，避免旧价格被重新解释。
- 按年、月、类型检索新品、促销和重要变化；促销时间带按活动日期展示。
- 新增产品线下的型号与具体变体，将平台商品链接归到同款；不同平台和卖家分别成列。
- 点击价格打开历史抽屉，支持年份、月份、日期区间、三种价格图例、逐日明细及原页跳转。观察记录只追加，缺失超过两天的曲线不连线，同日曲线取最后一次记录。
- 记录售价、划线价、优惠券、适用条件、库存、评分和评论数。只对明确确认通用且可叠加的优惠计算券后价，缺失值不冒充零，价格不含运费与税。

新增五张 PostgreSQL 表：`competitors`、`competitor_products`、`competitor_listings`、`competitor_observations`、`competitor_events`。服务启动时幂等创建。前端在 `public/competitors.js` 与 `public/workspace.css`；接口在 `lib/competitors.mjs`。

已配置下述真实品牌、价格快照和官方动态；官网、社媒及平台的自动采集尚未接入。“暂停”目前仅为配置标记。Aster 为明确标注的虚构交互示例，只在浏览器内生成，不写入 PostgreSQL、不与真实数据混合。目前不提供从上线日开始的完整历史价格。

本版 12 项自动检查通过，覆盖原有功能、竞品保存、历史追加、优惠条件、市场币种保护、跨竞品关联校验和来源安全。已实测桌面 / 手机布局及“新增品牌 → 型号 → 平台 → 价格 → 刷新仍保留”的前端流程；验收用数据已清除。

## 外部 CLI、Agent API 与飞书通道（2026-10-25）

新增 `/api/v1`，带独立 Bearer 凭证、模块权限、请求标识与调用记录。覆盖资讯、竞品、搜索词、ASIN、任务状态及通知，当前 64 项操作，与网页使用相同业务服务。接入说明见 [Agent 接入手册](docs/AGENT_API.md)、[需求与实现设计](docs/外部通道与API需求设计.md) 和 [OpenAPI](docs/openapi-v1.json)。

前台入口为左侧「我的工具 → 外部接入」（`/#integrations`）。提供接入总览、API 与 CLI、事件记录、通知预览和投递记录五个页面。可以搜索接口、查看参数与权限、复制接入命令、下载协议及接入手册；事件与投递支持筛选、分页和详情。通知预览不保存事件、不入队、不发送。飞书暂未启用的状态来自实际配置，页面没有启用发送或创建凭证的按钮。支持桌面、手机和键盘操作。

```sh
node bin/north.mjs doctor
node bin/north.mjs capabilities
node bin/north.mjs search overview
node bin/north.mjs events list --after 0
```

CLI 可从任意目录调用；默认凭证文件为 `.runtime/integrations/north.json`，不应打印或提交。新 Agent 可用 `auth create --name 名称 --out 私密文件` 获取独立只读凭证；按需用 `--scopes` 授予业务权限。`auth list` 不显示密钥，`auth revoke UUID` 立即撤销权限。

事件流与飞书队列已实现；系统自动汇集接入后的重要监控变化与最终采集失败。可用 `notify preview --file event.json` 查看通知，用 `events publish --file event.json --key 业务唯一键` 保存自定义内容。另一台机器的飞书 Agent 也可以按游标读取事件。

直接飞书发送默认关闭。本机需配置官方 `lark-cli`、机器人权限与接收群后再设置 `NORTH_FEISHU_ENABLED=1`。本次没有向飞书发送消息；API 也未发布到公网。服务继续绑定本机；远程接入使用 SSH 隧道或仅代理 `/api/v1/` 的 HTTPS 网关。
